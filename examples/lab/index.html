Mask lab

The same cutout applied three ways. Compare the halo edges, ideally on a high-DPI display.

What each browser shows

  • Chrome / Edge / Firefox: all three cutouts render, all crisp. (Chromium rasterizes image masks at device resolution and supports reference masks.)
  • Safari: first cutout renders with ~1px soft edges (WebKit rasterizes image masks at CSS-pixel resolution); second circle shows no cutout at all (WebKit ignores SVG reference masks on HTML elements); third — content wrapped in svg > foreignObject, masked in SVG context — renders crisp (measured 1 blend px vs 3 at 2×).

The library uses image masks: slightly soft on Safari beats absent, and the crisp foreignObject route requires restructuring the content DOM (candidate future opt-in mode — see README).

Tried against the softness

All verified no-ops on WebKit (screenshot byte-comparison or edge measurement):

  • Oversampling the mask SVG's intrinsic size (2× + viewBox)
  • transform: translateZ(0) / will-change: transform / isolation: isolate (compositing-layer tricks)
  • mask-mode: alpha (image masks are already alpha)
  • -webkit-mask-box-image (same edge blur, different slicing geometry)
  • SVG reference masks (mask: url(#id)) — not soft but absent: WebKit ignores them on HTML elements (the right-hand demo above)
